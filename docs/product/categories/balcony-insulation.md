# Категория: утепление / отделка балкона и лоджии

```yaml
categoryId: balcony-insulation
name: Утепление / отделка балкона и лоджии
shortName: Утепление балкона
synonyms:
  - утепление балкона
  - утепление лоджии
  - тёплый балкон
  - отделка балкона
  - отделка лоджии
  - ремонт балкона
  - обшивка балкона
seasonality: высокий спрос осенью и перед холодным сезоном
status: pilot
```

Этот файл — первая эталонная category spec. Он должен служить ориентиром при добавлении следующих категорий.

## 1. Что входит в категорию

Основные задачи:

- утепление балкона/лоджии;
- утепление пола, потолка, стен, парапета;
- устройство тёплого контура;
- внутренняя отделка после утепления;
- подготовка балкона к круглогодичному использованию;
- частичный ремонт/переделка существующего утепления;
- сопутствующие работы, если они являются частью утепления.

В рамках одного ТЗ могут присутствовать:

- демонтаж старой отделки;
- утеплитель;
- пароизоляция;
- обрешётка;
- черновая/чистовая отделка;
- пол;
- потолок;
- электрика;
- освещение;
- тёплый пол;
- откосы;
- подоконники;
- вывоз мусора.

## 2. Что не входит автоматически

Соседние категории, которые нельзя молча смешивать:

- установка/замена окон как самостоятельная задача;
- ремонт фасада;
- кондиционирование;
- объединение лоджии с комнатой с перепланировкой;
- сложные конструктивные изменения;
- остекление без утепления;
- изготовление мебели на балкон.

Если такие работы критичны для результата, сервис должен отметить их как смежные и уточнить объём.

## 3. Типовые Jobs to be Done

Пользователь хочет:

1. сделать балкон тёплым для использования осенью/зимой;
2. убрать холод/сквозняки;
3. утеплить только отдельную стену/пол/потолок;
4. сделать кабинет/зону отдыха/хранения;
5. заменить неудачное старое утепление;
6. получить отделанный «под ключ» балкон;
7. понять реальную стоимость, не разбираясь самому в материалах и технологии.

## 4. Intake — обязательные данные

### 4.1. География

```yaml
field: city
label: Город / район
required: true
why_needed: география исполнителя, выезд, логистика
```

### 4.2. Тип пространства

```yaml
field: balcony_type
label: Балкон или лоджия
required: true
values:
  - balcony
  - loggia
  - unknown
```

### 4.3. Размеры

Желательно получить:

- длину;
- ширину;
- высоту;
- площадь поверхностей, если пользователь знает;
- размеры отдельных участков, если утепляется не всё помещение.

Если пользователь даёт составные размеры, сервис может рассчитать приблизительную площадь, но должен явно пометить вычисление как расчёт по введённым данным.

### 4.4. Что утеплять

```yaml
field: insulation_scope
values:
  - walls
  - floor
  - ceiling
  - parapet
  - one_wall
  - full_contour
  - unknown
```

### 4.5. Остекление

Нужно уточнить:

- есть ли остекление;
- холодное или тёплое;
- требуется ли его замена;
- известно ли состояние монтажных швов/примыканий.

### 4.6. Текущее состояние

- голые стены/бетон;
- есть старая отделка;
- уже есть утепление;
- есть сырость/конденсат/промерзание;
- неизвестно.

### 4.7. Желаемый результат

- просто уменьшить холод;
- круглогодичное использование;
- кабинет;
- зона отдыха;
- хранение;
- отделка под ключ.

### 4.8. Отделка

Уточнить, нужна ли чистовая отделка и какая предпочтительна:

- панели;
- вагонка;
- гипсокартон + финиш;
- ламинат/другое покрытие;
- без отделки;
- исполнитель предлагает вариант.

### 4.9. Дополнительные работы

- электрика;
- освещение;
- тёплый пол;
- демонтаж;
- вывоз мусора;
- мебель/хранение — как отдельная смежная задача.

### 4.10. Фото

Фото желательно запрашивать, потому что они помогают оценить:

- геометрию;
- состояние стен/парапета;
- текущее остекление;
- объём демонтажа;
- проблемные зоны.

## 6. Discovery strategy

### 6.1. Компании

Примеры поисковых запросов:

- `утепление балкона {city}`;
- `утепление лоджии {city}`;
- `отделка балконов {city}`;
- `балкон под ключ {city}`;
- `ремонт и утепление лоджии {city}`.

### 6.2. Частные мастера

Источники/запросы:

- Яндекс Исполнители;
- Avito;
- другие разрешённые профильные площадки.

Запросы должны содержать категорию + географию и избегать чисто информационной выдачи.

### 6.3. Источники

Приоритетный пул:

- официальный сайт;
- web search;
- Яндекс Карты;
- 2GIS;
- Яндекс Исполнители;
- Avito.

Карты/каталоги могут быть discovery-источником, но для глубокого enrichment компании желательно определить официальный сайт.

## 7. Exclusion rules

Исключать/понижать:

- статьи «как утеплить балкон своими руками»;
- магазины материалов без услуги монтажа;
- оконные компании, если утепление/отделка не является их реальной услугой;
- каталоги организаций без собственного исполнения;
- исполнителей из другой географии без подтверждённого выезда;
- страницы, где категория упоминается только случайно;
- строительные компании общего профиля без признаков выполнения балконных работ — `needs_review`, а не автоматический высокий приоритет.

## 8. Qualification — must-have

Для сильной квалификации желательно минимум одно из:

- явная услуга `утепление балкона/лоджии`;
- `балкон/лоджия под ключ` с утеплением;
- подтверждённые примеры профильных работ;
- профиль исполнителя с соответствующей категорией.

Плюс география должна соответствовать задаче или должен быть подтверждён выезд.

## 9. Strong positive signals

- отдельная профильная страница услуги;
- фото/портфолио именно балконов/лоджий;
- описан состав работ;
- указаны материалы;
- опубликована гарантия;
- официальный сайт + телефон + email;
- работа в нужном городе/районе;
- понятный выезд/замер;
- прозрачное описание «под ключ».

## 10. Verification fields

Нужно пытаться проверить:

- профильная услуга;
- география;
- телефон;
- email;
- официальный сайт;
- замер;
- гарантия;
- сроки;
- опубликованная цена/цена от;
- состав работ;
- материалы.

Статусы использовать строго:

- `confirmed`;
- `claimed`;
- `unknown`;
- `risk`.

## 11. Contact enrichment

### 11.1. Website

Для компании определить официальный сайт, если возможно.

### 11.2. Email

Искать публичный contact email:

- на целевой странице услуги;
- главной;
- `Контакты`;
- `О компании`;
- `Реквизиты`.

Статусы:

- `found`;
- `no_website`;
- `not_crawled`;
- `not_found`.

При `found` сохранять `emailSourceUrl`.

### 11.3. Phone

Телефон можно получать с официального сайта/официального профиля/карт, сохраняя provenance.

## 12. Risk / reputation layer

Category-specific сигналы:

- явные жалобы на невыполнение оплаченных работ;
- массовые жалобы на скрытые доплаты;
- жалобы на существенное расхождение фактической цены с заявленной;
- подтверждённые проблемы с юридическим лицом/деятельностью, если релевантный публичный источник доступен;
- признаки несуществующей/подменной компании.

Никогда не формулировать непроверенное как факт сервиса.

Формат:

`Источник X сообщает/содержит ... → сигнал требует внимания`.

## 13. Uniform offer request

Базовый запрос исполнителю:

> Здравствуйте. Нужен расчёт по утеплению/отделке балкона (лоджии) по описанным параметрам. Просьба указать итоговую стоимость, отдельно пояснить, входят ли материалы, перечислить основные работы, предложенные материалы/толщину утепления, срок выполнения, условия замера и гарантию. Если какие-либо необходимые работы не входят в расчёт, укажите их отдельно.

В запрос автоматически добавляются нормализованные параметры задачи.

## 14. Обязательные вопросы исполнителю

1. Какова итоговая стоимость?
2. Входят ли материалы?
3. Какие конкретно работы входят?
4. Какой утеплитель/материалы предлагаются?
5. Какая толщина/система утепления предлагается, если применимо?
6. Какой срок работ?
7. Нужен ли платный/бесплатный замер?
8. Есть ли гарантия и на что именно?
9. Какие возможны дополнительные расходы?
10. Нужно ли что-то отдельно делать с остеклением/парапетом/примыканиями?

## 16. Нормализация цены

### 16.1. Главный показатель

Для сравнения стремиться к `comparableTotalPrice` — цене максимально близкой к полному объёму исходного ТЗ.

### 16.2. Цена «от»

Опубликованная цена `от X ₽` не является предложением по ТЗ.

Она может отображаться только как:

`Опубликовано на площадке / сайте — от X ₽. Это не расчёт по вашей задаче.`

### 16.3. Материалы отдельно

Если материалы не включены, предложение нельзя автоматически считать дешевле предложения `всё включено`.

### 16.4. Неполный состав

Если отсутствуют важные работы, система должна:

- показать неполноту;
- не делать категоричный вывод о выгодности;
- при необходимости сформировать уточняющий вопрос.

## 17. Что значит «всё включено» для категории

Фраза может использоваться только если из ответа/предложения понятно, что в сопоставимую цену входят необходимые для данного ТЗ основные работы и материалы.

Не использовать `всё включено`, если неизвестны:

- материалы;
- отделка при наличии её в ТЗ;
- демонтаж, если он необходим;
- критичные дополнительные работы.

## 18. Ranking до ответа

Факторы приоритета:

1. прямое соответствие услуге;
2. география;
3. официальный профиль/сайт;
4. качество профильных фактов;
5. доступность контактов;
6. provenance;
7. наличие информации о гарантии/замере/составе;
8. отсутствие risk signals.

Публикуем не балл, а объяснение.

## 19. Ranking после ответа

Основные факторы:

- сопоставимая итоговая цена;
- полнота работ;
- материалы;
- срок;
- гарантия;
- количество неизвестных условий;
- соответствие исходной задаче.

Примеры объяснений:

- `Самое полное предложение по исходному ТЗ`;
- `Стоимость ниже, но материалы оплачиваются отдельно`;
- `Дороже, но включает отделку и демонтаж`;
- `Не указан срок — требуется уточнение`.

## 20. Shortlist policy

Основной shortlist:

- цель — 3 сильных кандидата;
- максимум — 5;
- лучше 2 сильных, чем 5 слабых.

При более глубоком тарифе исследуем больше кандидатов, но не увеличиваем основной shortlist выше 5.

## 21. Карточка кандидата

Показывать:

- компания / частный мастер / тип не подтверждён;
- название;
- географию;
- `Почему подходит`;
- подтверждённые факты;
- заявленные факты;
- неизвестные факты;
- risk signals;
- телефон/email;
- источник контакта;
- источники проверки;
- опубликованную цену с оговоркой;
- доступные outreach channels;
- статусы ответа.

## 22. Comparison output

Основной экран сравнения должен фокусировать пользователя максимум на 3–5 предложениях.

Приоритетные поля:

- итоговая сопоставимая цена;
- материалы включены/нет;
- ключевые работы;
- срок;
- гарантия;
- замер;
- дополнительные расходы;
- неопределённости;
- объяснение, чем предложение отличается.

## 23. Test scenarios

Минимальный тестовый набор:

1. Полное утепление лоджии под ключ.
2. Утепление только одной стены.
3. Утепление пола + потолка без отделки.
4. Переделка старого утепления.
5. Тёплый балкон под кабинет.
6. Кандидат из карт без сайта.
7. Компания с сайтом, но без email.
8. Компания с email на странице контактов.
9. Дубли компании из web + 2GIS/карт.
10. Avito-кандидат с ценой `от`.
11. Ответ `31 000 ₽`, но материалы отдельно.
12. Ответ `37 000 ₽`, всё включено.
13. Ответ `48 000 ₽` с дополнительными работами.
14. Ответ без срока.
15. Кандидат с нерелевантной оконной услугой без утепления.

## 24. Что ещё нужно уточнить до production

- оптимальный discovery depth для тарифов;
- правила поиска официального сайта для кандидатов из карт/2GIS;
- обход contact pages crawler'ом;
- точная модель `emailStatus` + `emailSourceUrl`;
- category-specific weighting ranking;
- правила автоматического определения `comparableTotalPrice`;
- какие репутационные источники подключать первыми;
- какой минимум ответов нужен, чтобы сервис формировал уверенную рекомендацию.
